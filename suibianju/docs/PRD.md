# 随便局 · PRD

第二轮已实现的增量与状态合同见 [V2.md](V2.md)：自愿预算建议、无副作用预演、3–5 位虚构角色、逐人表态引导与决定单导出。以下保留首版问题定义和真实多人 P1 边界；首版“固定三人”的范围已由第二轮扩展为 3–5 人本地模拟。

## 背景与假设
朋友都说“随便”，提议却不断被否决。待验证假设：约饭的困难部分来自预算、忌口和位置等限制未被表达，而不只是缺少推荐。没有调研、用户规模或效果数据支持这一假设。

目标用户是 3–5 位约饭的朋友。发起人录入候选，成员确认自己的条件，所有有效成员对同一候选明确接受才形成决定。产品不代替成员拍板。

## 目标与取舍
P0 完成表达条件 → 本人确认 → 规则筛选 → 发现冲突 → 自愿调整 → 共同确认。以一分钟可理解的单人演示验证机制，不验证真实多人隐私或模型效果。

当前官网是 GitHub Pages 静态站，没有已核实的后端或模型配置。因此 P0 只发布**单人模拟体验**：三位虚构人物、四个虚构候选，角色可切换。页面明确告知其非真实协作，禁止输入真实敏感信息。真实饭局入口展示能力缺口，不生成假邀请链接。无需新增付费服务或密钥。

P1：3–5 人真实房间、服务端角色权限、房间删除与过期清理、受保护的模型整理。需另行选定后端及预算并完成安全验收后开放。

非目标：旅行、日程、账号平台、订位、支付、地图、实时商家数据、自动发消息、多 Agent、人格分析。

## 核心功能与恢复
| 功能 | 输入与展示 | 可修改内容 | 出错后继续 |
| --- | --- | --- | --- |
| 表达条件 | 原话或直接结构化填写；展示必须满足、尽量满足、明确排除、暂不确定四栏 | 预算上限、商圈、是否无辣、排除菜系、偏好菜系 | 草稿即时本地保存；失败重试或手动填写 |
| 模拟整理 | 内置规则识别少量示例，不声称真实模型理解；不确定语句留原文并提醒手填 | 所有整理项在本人确认前均可改；软表达只填软偏好或待澄清提示 | 可注入模拟故障；保留原话和结构化草稿 |
| 少量澄清 | 仅当存在价格已知且高低不同的候选，预算表达又模糊时询问预算上限 | 填数额或留空跳过；跳过不生成硬限制 | 回到手动表单 |
| 确认条件 | 保存规范化后的条件，并显示本人摘要 | 随时重新提交；未提交成员阻止最终确定 | 无效数额拒绝；保留输入 |
| 候选与推荐 | 菜系、预算区间、商圈、是否提供无辣；价格未知照实显示 | 编辑候选名称、菜系、预算区间、商圈与无辣情况，或增加信息不完整的虚构候选 | 缺失相关字段时列为“信息不足”，不能宣称满足硬条件 |
| 发现冲突 | 全员已提交才生成结果；最多展示 3 个共同可行候选及软偏好取舍 | 成员自愿改条件，或发起人补充候选 | 无交集明确展示预算/商圈/忌口/排除/未知类型，不归因到人 |
| 共同确认 | 当前演示角色接受、暂不接受或撤回；共享区仅显示确认数量与状态 | 改选会替换该角色的选择 | 重复点击幂等；同一候选全员接受才“已确定” |
| 结果失效 | 条件、候选、有效成员变化会递增版本并清除全部旧表态 | 演示角色退出/重新加入 | 未提交、少于 3 人时无法生成最终决定 |
| 生命周期 | 单机演示存浏览器，24 小时到期；加载和定时检查清除过期数据 | “删除本地演示”立即清除并进入空态；可重新开始 | 损坏存储恢复空态；存储不可用时提示刷新可能丢失 |

## 页面与状态
单页含：产品与演示说明 → 饭局状态及模式入口 → 演示角色 → 条件编辑/确认 → 公共候选与表态 → 本地模拟统计 → 边界与数据管理。

状态：收集中、待确认条件、可协商、无共同可行候选、等待表态、暂不接受、已确定、旧确认已失效、演示已到期/删除。未知信息不视为已满足。草稿编辑不改变已确认条件；只有再次确认才触发重算。

## AI 与程序分工
未来模型只输出可编辑草稿、必要澄清及解释。当前以明确标识的本地规则模拟这些入口，不发出模型请求。任何非支持语句都不推断隐含条件；“最好”“不想”“别太高”不自动升级为硬条件。模型未来接入时仍不能直接更新已确认条件。

规则层取预算区间上界与上限比较，精确匹配商圈、无辣与排除条件；相关字段未知则不进入可行集。软偏好按满足的人数排序、原顺序打破同值，不展示伪精确匹配分数。解释描述软偏好和已知限制，不声称实测距离、排队或营业状态。

## 隐私与数据边界
P0 不具备真正隐私隔离：一个浏览器能切换所有虚构角色，数据在 localStorage，任何同机使用者或同源脚本可能访问。页面明确说明，不能将隐藏原话等同于权限保护。无分析服务，无偏好上传、无外部字体请求、无密钥。

P1 必须在服务端分离公共房间/候选与私密原话/条件，使用不可猜测的成员凭证并验证所有读写；发起人也不能读其他成员私密条件。公共接口仅返回可行候选、汇总状态及必要冲突类型。需验证越权读写均拒绝。小群体仍可能推断信息，不承诺绝对匿名。

P1 房间拟保留 24 小时，需服务端 TTL、主动删除、过期拒绝访问；此为设计而非已实现能力。模型必须经服务端代理、请求大小限制、每成员及 IP 限流、超时与结构校验，不在前端放密钥；失败保留草稿并支持手动继续。真实模式开放前须确认供应商数据政策。

## 指标定义（没有真实试用结果）
- 共同确认耗时：最后一名有效成员完成条件确认到同版本全员接受同一候选；成员/条件/候选变化重开计时，旧轮保留为未完成轮。
- 达成率：观察期内形成共同确认的真实饭局数 / 已完成全员条件收集的真实饭局数；到期未达成计未完成，不能以生成推荐代替达成。
- 协商负担：推荐后暂不接受、条件修改及重新生成的事件次数，按饭局/版本统计；重复点击不重复计数。
- 理解修正率：未来真实模型抽取项中由本人纠正的项数 / 经本人审核的抽取项数；当前规则模拟不用于计算模型效果。
- 安全：违反已确认硬条件的推荐条数 / 推荐条数。功能测试要求零违规，不据此声称真实场景零风险。
- 采用与复用：后续经自愿回访问是否真的采用及愿意再次使用，单独记录样本数与日期。

当前仅有本机模拟事件计数和当前轮耗时，不发送分析日志，不记录原始私密偏好到事件日志，不作为用户效果数据。

## 验收与未决问题
自动测试覆盖正常一致、模糊表达、未知字段、无交集、硬条件不可突破、修改/退出/加入/候选编辑清空旧确认、未提交、少于三人、重复点击、过期/损坏存储、模拟整理失败与手动恢复。浏览器覆盖刷新、表态、键盘、手机布局、官网入口和源码链接。

他人无法读取私密偏好、跨设备同步及真实模型失败属于 P1 验收，P0 明确不适用，不能报为通过。未决问题为后端供应商、模型预算及政策、邀请链接转发后的成员认领、房主恶意删改和真实试用招募；均不阻塞单人演示发布。

## 四项预览的边界

| 预览 | 关键操作 | 来源与不会发生的副作用 |
|---|---|---|
| Eval | 保留历史 2/5 → 定位原句 → 试选独立复核结论 → 清除 | 原 e06 记录，人工判断仅存在当前页面，不修改原始分数或历史模型记录。 |
| 偏爱 | 同内容仅变字体 → 选择 → 明确 once/work/global 范围 → 撤回 | 直接调用完整工具的 `Room`、`createComparison`、`applyComparison` 与 `manage`。独立内存对象，不调用保存或恢复适配器。完整入口只携带构图方向。 |
| 随便局 | 已确认 40 元与预演 40/85/110 元并排 → 0/1/2 个可行选项 → 等待本人及全员确认 | 直接调用 `previewConditions`；不应用草稿，不写投票，不修改完整饭局。 |
| Bundle | 确定性挖掘中的候选 → 新增/让利账本 → 验证清单 | 从固定源码与 4,000 条合成订单中提取候选，用原纯函数计算。采纳率是假设，不是实际效果。 |

Bundle 选择“可乐 + 鸡腿饭”是为了演示折扣稀释，未声称它是收益最高的候选。候选中含任一商品的覆盖订单为 808 笔，原本买全 222 笔。5%/50% 的未买全者采纳假设，对应单均新增贡献约 −0.764/+0.965 元。金额是覆盖订单均值，保留三位，不是支付金额或收益预测。

## 案例归属

旧生成器按共享 `caseId` 将同一篇研究的 context、approach 和 result 写到不同项目。现在仅当 `study.project === project.id` 才能写入项目本身的说明；关联研究只能获得明确的“关联案例”标签。

Growth、Pricing、Filing 分别生成 `/cases/growth/`、`/cases/pricing/`、`/cases/filing/`。每篇保留自己的问题、取舍、验证范围和完整工具地址。套餐原案例保留关联工具入口，但不代替其他项目的设计过程。案例标题大于摘要；重复截图不在同页再次展示。

`/cases/agent-workflow/` 基于网站已有公开项目说明整理输入、工具结果和人工接管，链接已有的 Eval 和随便局实现与固定源码。它是流程拆解，不是客户系统、生产 trace 或新增业务成果。真实客户材料未加入本轮。

四条原 AI 观点及来源原文保留，新增自己的实践链接；背景脚本沿用原有参考链接选择器，避免重复插入来源。

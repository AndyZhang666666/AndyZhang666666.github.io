## 完成要求（逐项目记录，不用总绿灯替代）

1. **来源与可运行性**：确认权威源码、当前提交、实际发布目录/工作流和入口。现有脚本先读再运行，不调用需要真实 Key 的模型评测脚本。
2. **产品与结果**：每个 Demo 都有一个明确任务、真实可完成的输出及有用取舍；修正混淆概念、结论和计算，不为“加功能”堆外围按钮。
3. **状态与恢复**：正常、空/无结果、非法/极端输入、修改后失效、取消/重试、刷新/本机数据、下载/复制按适用性检查。缺失必须记为未完成或真实不适用。
4. **视觉与交互**：先截图再改。每个产品沿用适合自己的数据对象与风格，主任务清楚、字号和间距一致、无装饰噪音；1440/768/390 与必要的窄屏、键盘、减少动画检查，修改后复看实际截图。
5. **验收**：保留原测试，新增覆盖被修问题的测试；实际浏览器走完整任务和高风险恢复路径，检查产物内容，而不只看按钮存在。初始快照不是完整验收。
6. **仓库与发布**：README、具体使用说明、数据与能力边界、CHANGELOG、验证命令与证据同步；真实分阶段提交，推送后确认远端 SHA、构建及线上流程。
7. **官网一致性**：只按真实交付更新项目说明与入口，保留其他资料；双语、主题、站内体验和源码链接回归。

## 推进顺序

全量盘点与基线 → 按实际严重程度修复（旧扑克工具优先核对）→ 每个项目完成一个真实可验收闭环 → 所有已改项目的截图/回归 → 全量线上复验与交付索引。某个项目缺源码不阻止其他项目工作，但不会因此缩小最终范围或宣布全部完成。

## 非承诺

“完美”不能用主观评分证明。本轮完成要有逐项证据、无未解决的关键任务缺陷；未做真人研究、真实模型效果验证或完整安全/无障碍认证时，明确记录而非捏造。不可用静态回放冒充联网模型，不可用本机多角色冒充真实多人，不改真实业务成绩或履历。

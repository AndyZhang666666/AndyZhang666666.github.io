# 两个生活 Demo：从能演示，到有判断

2026-10-24。基于官网仓库 main `789f016` 的独立 checkout，不改履历，不改有据与其他 Demo，不迁移框架、不新建付费服务或公有仓库。新增的是完整本地交互，不把模拟当真实协作、真实模型或已验证产品效果。

## 产品判断与本轮交付

| 产品 | 已有基础 / 问题 | 本轮闭环 | 特意不做 |
|---|---|---|---|
| 随便局 | 硬条件与共同确认成立；无交集只让人自己改，结果没有可带走载体 | 3–5 位模拟成员 → 条件 → 无交集的最小预算调整建议/信息缺口 → 预演 → 本人确认 → 逐人表态 → 决策单复制/下载 | 不放宽忌口、排除菜系或位置；不自动接受、订位或真实邀请；不用“公平分”代替共识 |
| 偏爱实验室 | 记忆和仲裁成立；整张海报选择同时改变多维，难归因 | 保留首次直觉线索 → 单变量对照与“都不选” → 明确范围 → 跨内容验证 → 可撤回的记忆管理 → 导出偏好说明书与 SVG 作品 | 不把启发式百分比当准确率；不把一次偏爱存成永久授权；不接生图或公网模型代理 |

## 交互合同

- 随便局的建议只写入本人草稿，预演对原状态零副作用；确认才触发版本更新、清除旧表态。过期建议、未提交成员、未知信息不得绕过筛选。忌口与明确排除不主动提出降低建议。
- 无交集建议需要满足可解释前提：只缺价格时先补信息；仅有预算冲突时给当前成员一个精确但自愿的上限变化，仍由全部成员重新确认。不编商家、价格和营业状态。
- 决策单只有同版本全部有效成员明确接受才成立；只包含公共候选、共同确认数、版本与核实提醒，不导出原话和按人归因的私密条件。
- 单变量对照同内容、同其他参数，仅改变被试维度；“都不选”不写偏好。对照点击先形成候选修改，明确选择适用范围后写记忆；取消、换场景不应偷偷提交。
- 记忆标签展示“明确规则/待验证线索/对照线索”，不用伪精确置信度。轨迹可展开但不挤占主任务。
- 存储仅本机；损坏、禁用、到期、异步取消、刷新都要有可理解状态。可导出的是自己的偏好，不承诺匿名或跨设备同步。
- 移动端控制可点、可键盘使用，无必须拖动的操作；现有主题与语言切换保留，官网入口不重复添加。

## 视觉方向

两个都是 app screen，采用 design-taste-frontend 的 framed-sheet；不是给原网站换皮。随便局以当前饭局状态、候选与“决定单”为自己的识别元素；偏爱实验室以真正由参数驱动的海报与单变量对照为识别元素。保留栈及可用交互，增大主要说明字号，压缩开发术语与重复免责声明。无装饰性发光、假指标或假评论。

## 验收与完成门槛

1. 正常路径和无交集/冲突/取消/失效/未知输入/本机恢复均有自动化或实际浏览器证据。
2. 原测试保留；因体验变化需改预期时注明原因，不删失败测试充通过数。
3. 桌面、平板、手机与窄手机走查；截图复查，真实产物下载检查；不伪称完整无障碍认证。
4. 新功能与未实现边界同步 README、PRD、验证记录和官网中英文说明；非本轮项目及学历/履历内容不变。
5. 真实阶段提交：方案 → 随便局闭环 → 偏爱实验室对照与产物 → 验证与官网同步。提交不回填日期、不捏造历史。
6. 发布前拉取并保留并行远端更新；Pages 成功后实测线上链接和关键路径。最后交付线上成品、真实更新与剩余边界，不以“完美”替代验收事实。

## 1. 产品目标、已确认决策与交付边界

### 1.1 为什么选这四项

| 项目 | 目标使用者与任务 | 访客最终带走什么 | 希望展示的产品判断 |
|---|---|---|---|
| Eval Lab | 创意文本作者、AI 内容产品人员，判断一份评价是否可信、应该如何修改 | 有原文依据的复核报告、处理清单和改稿版本关系 | 标准是否适用、证据是否支持评价、修改是否解决原问题 |
| 偏爱实验室 | 有活动、招募或内容发布需求的人，制作海报并逐渐形成可复用偏好 | 与画布一致的 PNG / SVG、可恢复的作品与偏好说明书 | 把创作、比较和记忆分开，偏好要在下一次创作里产生作用 |
| Bundle Lab | 运营、增长产品人员和小商家，比较商品组合与折扣方案 | 方案比较、收益账本、假设与试验计划 | 新增购买和既有顾客让利分开核算，结论取决于哪些待验证条件 |
| 可信 RAG | 运营、行政等处理制度咨询的人，对照资料判断一件具体事情 | 有适用来源的答复草稿、待补信息、完整证据记录 | 检索到资料之后，还要判断适用性；缺少关键条款时不能替人补规则 |

前三项继续保留。RAG 接替通勤的默认精选位置，补足业务资料与 AI 应用方向。通勤完整工具、源码、案例和地址继续保留在作品库。随便局仍是创新项目，本轮不重构其内部功能。

### 1.2 用户已经确认的约束

1. 四项作为同一个升级批次，提供一个总览入口、统一变更清单与完整交付；内部按项目分步实现，不等于四项必须在同一提交里完成。
2. 四项的主要体验和本轮验收不依赖付费模型，不使用用户自己的付费 Key，不为公开访客开放无上限调用。
3. RAG 保留可接入真实 API 的架构。本轮完成接口和协议检查，不购买托管、不启用公开模型服务；未实测的真实模型能力单独标为待验证。
4. RAG 支持访客自己的资料，同时提供足够详细的内置任务。示例完整度通过正常、修改、缺项、冲突与恢复路径衡量，不通过堆预设问题数量衡量。
5. 官网继续使用当前主版本，保留首屏、主题、背景、毛玻璃、按钮反馈及其他已有动效。只调整精选作品、相关卡片和四项设计过程。
6. GitHub 记录实际开发过程，不伪造日期、作者、用户反馈、测试结果或模型运行。
7. 最终先交付本地可审阅版。代码可推开发分支；合并主分支与公开发布在审阅通过后进行。

### 1.3 成功标准

共同北极星：**有效任务完成率 = 能独立完成指定任务、解释结果依据并带走当前有效产物的尝试数 / 全部实际尝试数**。它是后续人工试用指标，本 PRD 不填造已实现的比例。

- 首次访客目标：约 3 分钟完成一次示例判断；这是设计目标，不是已有用户效果。
- 自有材料任务：四项都能脱离固定示例获得有用结果，范围与运行方式在界面上清楚可见。
- 工程完成：新增主路径及受影响边界实际通过，草稿和旧记录兼容，导出与当前有效输入一致。
- 可展示完成：真实界面、说明、入口、设计过程、GitHub 文档和提交版本对应同一批次。

### 1.4 本轮不扩展的范围

不重写官网其他区域，不迁移统一框架，不搭通用设计软件、通用企业知识库、在线协作平台或自动经营决策系统。已有 Eval 五维评分与 Bundle 两类人群计算模型保留；如发现公式本身错误，另立问题、版本和验证，不能在视觉修改里静默改掉。

## 2. 四个项目的功能规格与使用路径

以下功能均属于本轮交付，除明确标注“未来接入”的真实模型运行。

### 2.1 Eval Lab：从评价复核走到改稿闭环

#### A. 用户路径

首次示例：进入一条有争议的历史评价 → 点引用核对原文 → 查看标准适用性 → 留下人工判断 → 加入处理项 → 导出报告。

自有材料：建立原文版本 → 声明材料用途 → 自带评测结果或进行人工审阅 → 核对证据 → 建立处理项 → 新建修改稿 → 对照原稿与修改稿 → 导出。

#### B. 必须完成的功能

**1. 一个清楚的任务入口。**首屏并列“先复核一个案例”和“使用我的文本”。自己的任务顺序固定为准备原文、带入结果、复核与处理。模型名、温度、运行时间和声明等放在可展开区域，保留必要说明。

**2. 材料用途与标准适用性。**用途支持完整短篇、开场/片段、其他创意文本。现有五维标准继续使用原版本。片段等用途须显示结构完整性标准的适用性提示；用户可记录某个判断“不适用于本次用途”及原因，此记录属于人工解释层，不删除模型分数、不重算原均分。条件不一致时，比较页不直接宣布某版更好。

**3. 真正的免模型自有任务。**允许只带原文进入“人工审阅”。用户按五维检查、引用原文、记录意见与处理事项；模型原分显示“尚无模型评测”，人工意见不能计入模型复核或裁判一致率。以后带入模型结果时关联当前原文版本，不能把另一版原文的结果直接挂上来。

**4. 降低结果导入门槛。**继续支持现有 JSON 和任务包；允许粘贴纯 JSON 或单个完整 JSON 代码块，保留原始粘贴内容与规范化记录。仅去除代码围栏/首尾空白，不改分数、不补评语、不重写引用、不修正均分。错误指明字段及修复方式，失败不覆盖当前材料。

**5. 处理项与改稿建立关系。**处理项包括核查评语或修改原文，关联维度、原文位置和来源记录。新建修改稿时可选择本次处理的事项。勾选完成只代表已处理；是否解决由后续审阅记录确认。旧稿、旧评测和旧处理意见保持可查看。

**6. 有意义的对照。**同时显示文本改动、五维原始评价、人工争议和关联处理项。突出用户选中的问题；仅当确有同文多次结果时展示波动。人工审阅与模型评价分栏，不混算。缺模型信息、标准不同或用途不同均提示比较限制。

**7. 调整默认案例。**将现有“病历悬念·完整稿”的展示名改为“病历悬念·句子补全稿”，保留样本 ID、原文、历史分数和链接。用原始评语说明：补完句子不等于形成完整叙事弧。再提供一个有完整闭环的现有样本作为区别，不能改历史成绩来配合文案。

**8. 统一报告。**Markdown 先列尚未解决的问题和下一步，再附原文版本、评测条件、原始评价、提供过的中文释义、人工判断与处理历史。保留 JSON；没有模型评价的报告明确为人工审阅报告。

#### C. 状态和兼容

- 原文编辑保留为工作稿；确认新建版本后生成新版本关系，旧模型结果只属于旧稿。工作稿未评测时不能显示旧稿为当前结果。
- 继续兼容现有复核 JSON v1、记录标识、资料库、参考分及存储保护；新增工作稿与版本关联不改旧记录内容标识。
- 新建/编辑原文继续最多 20,000 字符；旧报告仍按原有读取规则兼容。原有单份导入 1MB、资料库 20 份及比较报告读取能力继续保留。达到限制先管理/导出，不自动淘汰旧材料。
- 新人工审阅与版本元数据使用独立扩展结构；旧版读入缺省为用途未声明、无版本关联。模型记录和无模型材料通过显式类型区分，缺分数不填 0 或模拟分。

#### D. 完成标志

用户能带自己的文本，在无 Key 的情况下形成可导出的人工审阅；也能导入自己的评价，说明一条争议依据，并在修改稿中找到对应处理。原始分数、人工意见和处理状态始终分开。

### 2.2 偏爱实验室：做成可使用的海报创作工具

#### A. 用户路径

做作品：选使用场景 → 填内容 → 选构图 → 调整适配 → 对照候选 → 导出成品。

探索偏爱：同内容选择两个方向或一个参数 → 比较 → 临时采用 → 选择是否记住及适用范围 → 换一份内容验证。

做作品是默认路径；探索偏爱与记忆保留，但不要求先做测试才能创作。

#### B. 必须完成的功能

**1. 六套构图继续保留。**瑞士现代主义、解构主义、编辑杂志、包豪斯几何、日式留白、双色印刷共用可扩展注册表。每套使用自身布局规则，缩略图实时使用当前同一份内容。

**2. 内容升级为真实发布需要的字段。**标题、副文案、类别、落款保留；增加可选日期/时间、地点、行动说明。空字段不占位置。提供展映、招募、分享会三套完整内容起点；切换起点前提示将替换的内容。

**3. 三种输出版式。**保留 900×1200 竖版，增加 1080×1080 方形和 1600×900 横版。切换尺寸重新布局，不能直接拉伸原图。六方向均支持三种比例；容量说明、字号、换行和密度调整随当前版式更新。

**4. 内容适配。**检测超界、遮挡和容量不足；保留原文，定位问题字段，提供“减小字号”或“调整换行/密度”的可预览操作。文字内容不被自动删改。未解决的遮挡/超界阻止成品导出，但允许保存草稿。

**5. 个人图片。**支持本机 JPG、PNG、WebP，一次一张主图、单文件最多 5MB；支持适合/填满和焦点位置，不做自由拖拽编辑器。图片进入各方向预留的主视觉区域，纯文字状态仍完整。拒绝远程图片链接和上传 SVG，避免导出依赖外站或执行内容。

**6. 两候选与历史。**保留两份独立作品快照，包含文案、比例、方向、参数与图片引用。对照结束返回当前画布原位置；采用候选不直接改长期偏好。恢复候选前展示将替换的工作内容，缺图片时明确提示并允许重新选择。

**7. 让记忆的效果可见。**保存前展示方向/参数、适用场景及会替换的规则。换内容后显示本次沿用了什么，可比较应用前后，可只对本张例外。原有范围授权、撤回与说明书往返继续保留。把“告诉 Agent”改为符合规则模式的操作表达；未识别输入保留原话并提供可用选项，不虚构理解。

**8. 导出。**PNG 为主要成品出口，SVG 保留编辑用途；两者来自当前同一渲染状态，含实际图片与尺寸，不含反馈和偏好日志。PNG 需与可见画布一致；SVG 明确字体依赖。偏好说明书单独导出，不混入图片。

#### C. 状态和兼容

- 草稿保留当前内容、图片、版式、临时方向；长期偏好和作品分开存储。
- 新图片放 IndexedDB，原有文字与记忆结构兼容；旧草稿默认竖版、无图片、新字段为空。存储不足保留当前画布并允许导出，不清除旧偏好。
- 对照绑定内容、尺寸、图片和候选参数签名；任何相关变化让旧对照待重新生成。
- 导出不保存长期规则；临时试用不扩大授权。按钮在当前场景已授权同方向时明确反馈已记住。

#### D. 完成标志

用户能用自己的内容和图片，在六方向及三种尺寸中完成一张无遮挡的海报；下一次使用新内容时，能看见已授权偏好怎样减少重复调整，并能撤销。

### 2.3 Bundle Lab：从经营假设走向可执行验证

#### A. 用户路径

先试一个组合或带入自己的商品 → 建立订单构成基线 → 填成本和行为假设 → 看贡献与让利 → 保存 A/B → 预演边界 → 选择或暂不选择 → 输出验证计划。

#### B. 必须完成的功能

**1. 重新组织输入。**先说明卖什么、优惠多少、预计多少未买齐者补齐，再展开成本、原有消费、已买齐比例及领折扣率。输入旁区分订单派生值、用户确认值与行为假设。现有五项来源说明继续使用，不重复增加另一套说明面板。

**2. 基线输入有两种方式。**手工方式先填覆盖订单数和原本已买齐数，再得到比例；未买齐者原有消费仍可明确填写。无订单时允许归一化 100 单，但不得显示为观测样本。

**3. 简化订单 CSV 导入。**必需列 order_id、sku；可选 unit_price。其他列只在预览中列明未使用，不自动解释支付、退款或数量。接受 UTF-8、最多 2MB、10,000 明细行、100 个 SKU；提供下载模板及粘贴入口。按订单聚合并按商品出现去重，明确这是“一单一商品集合”的单份构成模型，不是按实付金额核账。

用户选择 2–3 个商品，确认各自参考单价。存在多种单价时展示分布，不静默取第一行；必须确认统一参考价才能继续。CSV 解析处理引号和逗号，错误指出行号，不能沿用当前仅适合内置简单字段的宽松解析来静默吞错。

覆盖订单定义沿用现模型：至少包含一件所选商品的订单。按所选商品出现关系派生已买齐比例及按参考价重算的构成消费，再经适配层调用原计算函数。导入基线的订单数与每100覆盖单结果分别显示；采纳率、领折扣行为及成本仍非观测结论。数量和促销实付不进入本轮模型，页面、模板和报告都说明口径。

**4. 保留核心账本。**新增毛利贡献、既有顾客让利、增量毛利、平衡采纳率始终一起出现。保留零值、负值和不可达状态；毛利不能写成净利润，不把关联强度当活动效果。

**5. A/B/C 方案比较。**保留最多三份独立快照；A 为基准，突出相对 A 改了什么、增加了什么成本或假设。已保存方案不随当前滑杆变化，不把方案收益相加。选择理由可以暂存，确认后才写入决定。

**6. 条件地图。**继续共用原计算引擎，点击只预演、确认才采用。参数与预演同屏可对照，明确采纳率不会由折扣自动预测。零折扣下的采纳也是外部假设，不能暗示不优惠也必然新增购买。

**7. 生成验证计划。**从当前方案带入商品、折扣、人群口径、当前平衡点与待验证项。用户补充基线期间、试验对象、分流/对照方式、观察时长、主要指标和护栏。默认主要指标为覆盖订单口径的增量毛利，护栏包含退款/履约异常及原有购买被让利的情况。计划不得自动给出未经依据的样本量或上线门槛。

**8. 回填观察。**支持给计划录入试验/对照两组的覆盖人数、原本未买齐人数、补齐人数、原本已买齐且领折扣人数及成本来源，显示已知和缺失字段。可以检查率与原假设的差异，并明确选择是否复制为新的工作假设。原计划和原方案不被覆盖；只有描述性观察，不自动认定因果提升。

**9. 完整产物。**比较卡同时带方案差异、选择理由、基线来源、归一账本、待验证条件及计划。保留 Markdown/JSON 与复制入口；没有真实试验时显示尚无观察结果。

#### C. 状态和兼容

- 内置订单、手工假设、CSV 基线分开保存和标记；切换来源不互相覆盖。
- CSV 先预览、核实价格和口径，再确认应用。失败、取消、空数据均保留当前草稿和方案。
- 继续使用现有两类人群引擎及模型版本，不把输入适配当成计算模型升级。旧快照、导出和草稿可读；新计划、来源及观察结构独立扩展。
- 观察记录标为用户录入，未审计；不从少量结果自动生成价格弹性、收益概率或最优套餐。

#### D. 完成标志

用户能用自己的商品和基线完成两方案比较，解释哪项假设决定盈亏，并带走可以据此收集数据的验证计划；回填观察后可建立新方案，旧决定仍可追溯。

### 2.4 可信 RAG：制度与资料判断工作台

#### A. 定位与用户路径

首版业务范围固定为设备借用、续借、归还、损坏处理与采购资料咨询。保持只读判断和答复草稿，不执行借用、审批、支付或企业系统写入。

示例路径：选一件具体任务 → 补必要事实 → 检索适用资料 → 核对结论与缺口 → 调整条件重算 → 编辑/导出答复草稿。

自有资料路径：导入文件 → 预览文本与确认版本信息 → 输入任务或问题 → 检索并选择依据 → 整理草稿及待确认项 → 保存证据记录。

#### B. 三类运行能力

| 能力 | 本轮实际执行 | 用户看到的说明 |
|---|---|---|
| 内置规则任务 | 对原创资料真实检索、选择有效版本，使用明示规则计算支持的条件并组成草稿 | 免模型示例；规则处理，不是实时模型回答 |
| 自有资料 | 本机解析、真实文本检索、引用定位、用户确认事实与组织答复 | 我的资料；本机检索/证据整理；未经语义理解的条款不自动作结论 |
| API 接入 | 可本地启动的接口、模型适配器、开关、契约及失败检查 | 默认关闭；未配置/未实测；本轮不产生真实模型费用 |

不得在付费接口缺失时伪装生成成功。自己的任意文档不默认具有可执行规则：只有用户明确确认过的、属于本轮支持字段的条款才参与规则判断；其余只作为可检索原文和人工草稿依据。

#### C. 内置案例必须有完整任务

保留并扩充当前原创语料到约 24 份公开文档，包含版本、过渡规则、例外、来源冲突和干扰资料；管理范围测试资料继续独立供给，不进入公开包。所有机构、规则和人员均明确为虚构。

以下 12 项为必须完成的任务目录，每项配置任务背景、输入事实、适用来源、预期处理、至少一个可修改条件、一次异常/恢复路径和可带走的草稿。每项都调用同一检索及规则引擎，不用按按钮映射答案的脚本替代。

| 编号 | 任务 | 必须出现的判断 |
|---|---|---|
| R01 | 当前日期借显示器 | 原始快照适用14天规则，并展示来源和前提 |
| R02 | 查询历史借用 | 历史日期适用30天规则，旧版并非一律无效 |
| R03 | 改资料快照 | 修订快照对应10天，旧运行不被新资料覆盖 |
| R04 | 申请续借但缺借出日期 | 只追问会影响判断的缺失事实，保留已填内容 |
| R05 | 跨制度变更的续借 | 查过渡条款；没有说明时保留缺口，不能只按最新日期决定 |
| R06 | 满足明确条件的续借 | 逐项展示次数、预约等前提，修改事实后重新判断 |
| R07 | 不满足续借条件 | 说明具体未满足条件，允许回到事实核对，不替用户修改原条件 |
| R08 | 归还地点或办理流程发生变化 | 查当前适用流程，答复包含可继续办理的信息 |
| R09 | 损坏处理但没有赔偿金额条款 | 回答可确定的处理流程，金额保持未知，列明需确认对象/资料 |
| R10 | 询问不在公开范围的管理信息 | 只说明当前可访问资料不足，不泄露受限文档标题或片段；前端身份切换不冒充授权 |
| R11 | 同时有效、无法确定优先级的冲突条款 | 并列双方及差异，暂不替人挑一条；允许在取得说明后更新资料重查 |
| R12 | 借用不存在于资料库的设备 | 显示无充分依据与下一步，不能拿相近设备规则套用 |

新写续借等示例条款需与当前资料建立一致的版本与生效关系，并为每项写明人工可复核参考。原有14/30/10天历史案例继续可复现；新的构造材料不能冒充真实公司制度或真实模型效果。

#### D. 自有资料规格

- 支持 TXT、Markdown、可提取文字的 PDF；最多5个文件，单文件2MB、总计8MB、提取文本总计200,000字符。PDF 解析在本地 Worker 中完成；不做扫描件 OCR、加密文件破解、网页爬取、Word/Excel 或远程 URL 导入。
- PDF 使用本地打包的解析依赖，固定版本和许可证，不靠第三方 CDN 才能打开。无法提取文字时解释原因，提供粘贴文本入口；多文件可逐个移除失败项，不能静默漏页。
- 导入后展示标题、页/段定位、文本预览。用户确认文档组、版本、有效期间及其是否已知；不得把文件修改时间自动当制度生效日。
- 日期未知的文件可以检索，但不能被宣称适用于某业务日期；并列来源、缺少过渡说明等必须留给用户确认。
- 支持规则字段限设备/事项、时长、次数、有效期间和明示前提。可用明确句式提出候选值，但必须展示原文并由用户确认；复杂条件保持原文，不自动泛化。
- 对范围外问题提供检索与证据笔记，不装成通用语义问答。草稿从选中原句、确认事实和用户编辑组成，展示哪些句子有引用、哪些是人工补写。
- 切换回示例不混入个人资料；默认本机保存提取文本与工作状态，不上传原文件，不把内容写入公开 GitHub、截图、分析日志或示例库。提供逐文档移除、工作区导出与清除；涉及已引用资料时先说明会使哪些答复待重查，取消不改变现有工作。

#### E. 答复、工作记录与变化处理

结果状态固定为可形成草稿、需要补充事实、依据不足、依据冲突、范围受限或处理失败。无充分依据时仍能导出问题、找到的资料、缺口和下一步，不必制造一个确定答案。

每次结果绑定问题、任务事实、业务日期、资料版本/摘要及实际引文。资料、日期或事实改变后，旧答复保留原条件并标记待重查；不得重新标成当前答复。用户可编辑对外答复，人工新增内容单独标记。

产物支持复制答复、Markdown 答复单及 JSON 工作记录。默认不打包个人文档全文；只有显式选择才附来源文本。引用检查仅证明文字匹配，不自动显示“答案正确”。

#### F. API 预留与费用控制

- 复用当前 Node 服务和模型适配器。新增能力查询，默认显式关闭模型调用；前端不能通过改参数开启。未开启时返回明确的未启用状态，不请求上游。
- 继续使用现有会话及服务端范围检查；客户端不能传 role 自我授权。新工作区绑定所属会话，不能凭 workspaceId 访问另一会话资料。
- 为工作区创建、已提取文本导入、任务运行和运行导出增加版本化接口；保留现有 POST /api/run 及原始示例兼容。上传接口接提取文本和确认元数据，不直接替访客向外部模型传 PDF。
- 模型未来只接收本次获授权且适用的实际召回片段。权限、资料版本和规则适用性由程序维护，模型不负责扩大可用范围。
- 当前12秒超时、有限输出、会话限流与进程调用限制继续保留；本轮协议测试用明确的合成返回，不计为真实模型记录。未来公开模型服务的供应商、托管和持久费用上限另行确定，未确定前不可开启。
- 本轮交付 API-ready，不验收在线模型效果、不部署付费服务。官网仍能独立完成免模型主流程。

#### G. 完成标志

访客能完成12类示例的正常与异常任务，也能导入自己的文字资料，找到可适用或待确认的依据，形成可编辑、可导出的答复单。错误资料、未知条款或未配置 API 不会被伪装成确定结论。

桌面：左侧四个项目选择，右侧仅展开当前项目的短互动；手机：两行四按钮，下面是当前项目。所有内容不自动轮播、不整页嵌入完整应用。

| 项目 | 首页短互动 | 展示重点 |

### 3.2 四项工作区各有性格

| 项目 | 桌面结构 | 手机结构 | 视觉与动效重点 |
|---|---|---|---|
| Eval | 窄维度/任务队列＋原文＋当前评价与处理；对照沿用同一阅读位置 | 顶部当前维度，原文/复核两视图，选择与阅读位置保留 | 保留瑞士网格与清晰字重；引用定位、版本差异和保存反馈 |
| 偏爱 | 约280px内容面板＋占主位的画布；图库为缩略图带，记忆按需侧开 | 画布先见，编辑分组展开，导出就近；对照同位置切换 | 六构图各自规则；画布切换轻过渡，布局稳定、无长距离跳动 |

### 3.3 共通交互与可读性要求

- 以内容层次、对齐和留白建立秩序，减少同尺寸卡片堆叠；官网外壳保持，工具内部不强行套同一套米色管理后台。
- 正文默认16px左右，操作和长说明保证可读；重要状态不使用低对比小灰字。数字使用等宽数字，错误就地显示。
- 工作区最大宽度约1440px，桌面减少长滚动；主文档/画布有稳定空间，编辑后不把用户抛回页面顶部。
- 按钮按压约100–160ms，面板和画布切换约160–240ms；优先 transform/opacity，不为算法等待伪造延迟。减少动态效果时移除位移，保留状态反馈。
- 点击、键盘和触屏都可完成核心任务；焦点可见，弹层 Escape 关闭并返回触发处，触摸目标以44px为设计目标。颜色不独自承担正负、过期或成功含义。
- 不能让固定按钮遮挡输入、引用或手机安全区域。整页不横向溢出，必要的大表格在有说明的局部容器内查看。

## 4. 数据、接口与兼容要求

### 4.1 不更换现有技术栈

Eval 与 Bundle 保留现有 Next.js 工程；偏爱与 RAG 保留官网原生模块；RAG 的可选后端继续 Node。只共享必要的数据契约、设计规范与预览来源，不为一致性迁移成统一框架。

### 4.2 需要新增或扩展的对象

| 项目 | 扩展对象 | 最小约定 |
|---|---|---|
| Eval | 文本版本、用途上下文、人工审阅工作稿、处理项关联 | 模型记录沿用 sourceText / originalResult / reviews；无模型工作稿单独类型，不能以虚构 originalResult 填空。新增报告可读旧版，导出包含类型与版本 |
| 偏爱 | 作品内容字段、画布尺寸、图片资源引用、作品快照 | 授权规则仍按原场景与维度存；图片/尺寸属作品，不自动成为偏好。SVG/PNG走同一渲染状态 |

新增字段必须有格式版本与读取默认值。迁移前保留原始存储；先校验、再写入新值。损坏、容量不足或导入失败不覆盖当前工作。存储被禁用时允许内存操作与导出，并提示刷新可能丢失。

### 4.3 明确接口行为

- Eval 的结果导入、任务包和导出接口兼容旧记录；纯人工任务不能误进入依赖模型分数的聚合函数。
- 偏爱使用当前可扩展方向注册表和 SVG 渲染器扩展尺寸/图片，缩略图、画布、比较和导出不各维护一套布局。
- Bundle 原引擎输入输出保持；CSV/手工基线只经适配层转换。金额、百分比、缺失和不可达继续使用统一格式化方式。
- RAG 继续读取原 /api/run；新增能力查询与工作区/资料接口，版本化支持任务事实。未启用的模型请求在本服务内被拒绝；引用接口仍只返回所属会话当次实际使用的可访问片段。
- 原有 URL、项目稳定 ID、设计过程地址和旧参数链接保留。新增展示名不随意改变底层记录标识。

## 6. 验证、验收与批次实施顺序

### 6.1 控制验证量

复用已有计算与状态测试，只增加新能力、兼容读取和受影响路径的检查。每个功能阶段跑受影响检查，四项集成后做一次完整的本轮任务验收；没有新变更或失败不重复全量跑。主要任务免 Key，不发付费模型请求。

### 6.2 必须通过的实际任务

| 项目 | 主任务 | 重要异常/兼容 |
|---|---|---|
| Eval | 自己的原文人工审阅；带入结果→引用核对→处理项→修改稿→对照→导出再读取 | 坏 JSON不覆盖；单代码块导入；用途差异提示；无模型材料不伪造分数；旧报告/原分不变；原文变化不串结果 |
| 偏爱 | 自己的文案与图片，六方向/三比例可选，保留候选、比较、授权、换内容、导出 | 长文不丢；缩放/换行能修；替换与取消保留草稿；偏好可撤回；坏图/缺图/存储失败可恢复；PNG与画布一致 |
| Bundle | 模板/自有 CSV→预览→确认基线→两方案→条件预演→验证计划→回填→导出 | 多单价需确认；错误行/空文件不覆盖；实际单数和归一单位分开；零采纳/全买齐/不可达仍正确；预演不改方案 |
| RAG | 12类示例可改变事实；自己的 TXT/MD/文字PDF→确认资料→检索→组织草稿→导出 | 扫描/损坏/加密PDF；未知日期；冲突/不足/范围不符；资料改动旧结果过期；工作区隔离；无 API不发上游请求 |

RAG 另外保留少量不出现在示例入口的新问法/新条件作为留出检查，人工写明参考片段、应澄清事实与预期状态。检索命中、关键事实、引用支持性和拒答分别记录；合成接口返回只能验证协议，不能计为模型效果。

### 6.3 布局和操作验收

统一检查约390、768和1366px宽度；官网当前有效主题、键盘主流程、减少动态效果、图片或资源失败与一次刷新恢复。正文无裁切、全页无横向溢出、操作不被固定区域遮挡；大表格仅自身滚动。

导出文件至少每种新格式实际打开一次；SVG/PNG/Markdown/JSON与当前有效状态一致。网络失败、取消和重新进入不能丢材料。记录实际检查环境，不把自动测试等同真人研究或正式无障碍合规。

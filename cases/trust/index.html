要解决的问题

评分看完以后，作者到底应该先核查什么、修改什么？

固定样本只能让访客看懂界面。真正的任务是把自己的原文、外部评测、证据争议和待修改问题连起来；如果一切最后仍停在总分，作者带不走下一步。

独立实现历史回放、自有文本任务包、严格结果导入、本机材料库、逐维复核、处理清单、免 Key 记录对照和报告导出。五维、原 Prompt 与18条历史输出保持原样；本轮未重新调用模型。

方案与取舍

评测的下一步不应只是换一个总分，而是留下可追踪的问题、证据和处理选择。

只给总分

比较很快，但低分原因与高风险问题都容易被平均掉。

要求解释评分

解释更丰富，仍可能出现无据的理由或错误引句。

证据与复核分开

采用的做法：原始评分保留，人工复核另外记录；意见不一致也能留下来。

把判断变成机制

  1. 用自己的 AI，也能完成任务

    任务包带完整 rubric、原系统 Prompt 和返回格式。用户自行运行后带回 JSON；本站看不到外部对话，模型、运行条件与时间仅为来源声明，不作认证。坏文件和取消不替换当前材料。

  2. 原始评价与处理行动分开

    支持、存疑与需上下文分别记录。可把问题加入核查评语或修改原文的处理项，跟踪完成状态；完成处理不会回写原始分数，报告把未解决事项放在前面。

  3. 比较之前先核对条件

    本机库最多20份，两侧按维度 ID 对齐。原文、模型或条件不同会提示；同一记录不重复计数。重复观察展示均值与极差，极差不是置信区间，也不自动宣布赢家或允许发布。

验证、代价与下一步

6个样本的18次历史输出保持可回放。任务包、严格导入、资料上限、重复条件、处理项往返与报告顺序有程序检查；本轮浏览器集成证据另记，不能据此声称模型质量或生产准确率提升。

外部 AI 需要一次往返，但避免让公开作品集依赖共享 Key；五维限定创意文本，不能宣称支持任意评测体系。材料与人工判断仅在本机，库满不会自动淘汰旧记录。

用自己的文本走完“任务—返回—复核—处理—再次对照”，记录哪里需要补充说明。之后再邀请首次使用者，观察未解决问题是否更容易转成实际修改，而不是只问分数是否直观。

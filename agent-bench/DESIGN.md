# Agent 执行评测台 · 界面约定

更新：2026-10-30。范围仅为 `/agent-bench/`，保留官网和另外三个精选项目的现有界面。

## 主问题

工具没有返回，事情到底做成了吗？

第一屏给出工单任务、两个沙盒的共同起点和开始回放操作。响应丢失、权限不足、批准后版本变化是重点入口，其余七个案例仍在原生选择框中。初始说明不透露数据库已提交的结果。

## 布局与视觉

延续暖纸、墨色、锈色。参考 framed-sheet 的浅色面与细边线，保留现有系统字体，不增加侧栏、图像和装饰性数据看板。单页只有一个工作区，因而不引入 L 形侧栏。主体最大宽 1240px、左右各 32px；1176px 可用画布为 578 + 20 + 578。来源说明始终可见。

页面的特有元素是两条策略轨道：已发生的事件按原序号展开，选中事件带细边线和可见证据。事件序号是数据索引，不是装饰性章节编号。仅操作 ID、事件索引和原始代码用等宽字体。

桌面两条轨道并排。每条轨道顺序为工具回执、已读取的工单、证据来源和已回放事件。1440px 初始界面能看见两条轨道的标题和首行；开始回放会滚到轨道区域，控制条保持可用。手机保留紧凑双策略状态摘要，下面通过标签切换一条完整轨道，使用同一个游标。

控件最小高度 44px，主标题 28px，手机 23px；正文 14px，辅助文字 12px。交互容器 6px 圆角，轨道与复盘面板 12px。没有卡片投影或渐变。

## 状态不能相互代替

- 工具回执来自已访问的工具事件，未知回执用琥珀色。
- 回放中工单字段只采用已访问的 `query_ticket.result.ticket` 或操作回执快照。
- 超时、执行中断、版本变化会将上次快照标为待核实，不能拿旧值冒充当前状态。
- 完整回放后才显示留档的最终数据库快照，并另列 Agent 最后已知的状态。
- 结果未知单独显示，不用运行失败的红色替代。正确拒绝可以符合预期，业务写入仍为零。
- 绿色字段只说明相对初始值发生变化；是否符合案例预期由原有判据决定。

## 回放与证据

开始、继续、暂停、上一步、下一步和直接看结果共用同一个只读游标。每条轨道保留自身事件顺序，较短轨道停在自身终点；相同序号不表示同时发生。

自动回放在缺失回执、只读权限、版本冲突、冲突后的新批准与查询故障处暂停。事件中的人工批准写明“留档中的批准”，不能变成可执行的确认按钮。可执行的确认、取消和恢复仅出现在原有本地运行模式。

事件详情展示调用的可见结果、返回代码、快照版本、原操作标识，以及可展开的原始 JSON。原始数据面板保留键盘焦点与内部滚动，长标识可以换行。复盘保留最终影响、结束声明、逐项判据、版本、来源和运行 ID，提供 Markdown 与原始 JSON 下载。

## 动效与输入

按钮按下轻微位移；新事件进入使用 200ms 位移和透明度；字段真的变化时使用 240ms 反馈。自动回放间隔为 850ms，明确属于阅读节奏，不代表实际执行耗时。

系统请求减少动态效果时取消 CSS 动画与平滑滚动，仍保留逐步控制和关键节点暂停。键盘可操作所有原生按钮和 disclosure；手机策略标签支持左右键、Home 和 End。切换不重放工具、不改变记录、不移动回放游标。

## 检查边界

设计检查器在 1440、768、390px 得到 0 FAIL；暖纸配色 warning 保留，依据是用户明确要求延续原网站风格。代码检查的等宽字体和补零序号 warning 分别用于原始代码/标识和真实事件索引。人工逐张查看对应截图，未将通过检查器当作设计奖或用户研究结论。
